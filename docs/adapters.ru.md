# PRUD AI e-com daily — адаптеры маркетплейсов

В версии разработки 0.2.0 добавлены экспериментальные модули получения данных из API и конвертации заранее сверенных CSV. Подключение реального кабинета выполняется только самим продавцом на его компьютере. Живых проверок с ключами продавцов пока не было.

| Площадка | Получение данных |
| --- | --- |
| Wildberries | Воронка по товарам за дни; отдельно история фактических рекламных затрат и статистика кампаний |
| Ozon | Аналитика заказов по SKU и дням; отдельно рекламные расходы Performance API |
| Яндекс Маркет | Заказ генерации отчётов по заказам и услугам; получение статуса и ссылки на готовый отчёт |

Инструкции, названия переменных окружения и команды: [adapters.md](adapters.md).

Все полученные данные сохраняются только локально в папке private/, исключённой из Git. Не передавайте токены через командную строку, не публикуйте выгрузки, подписанные ссылки и реальные идентификаторы. Папка private/ не является зашифрованным хранилищем.

Важно: полученный JSON — это исходные данные, а не готовый финансовый отчёт. У WB нужно раздельно сверять фактические списания и статистический расход. У Ozon аналитика заказов может не содержать суммы отмен; у Маркета отчёты формируются асинхронно и содержат транзакции разных типов. Пока не выполнена сверка и корректное распределение затрат по SKU, автоматическое вычисление чистых заказов, СПО и ДРР из исходного JSON не выполняется.

## Проверка без токенов

```bash
python -m unittest discover -s tests -v
python -m prud_ecom.adapters map-csv --kind sales --input examples/source-sales.csv --mapping examples/mapping-sales.json --output demo-sales.csv
python -m prud_ecom.adapters map-csv --kind ads --input examples/source-ads.csv --mapping examples/mapping-ads.json --output demo-ads.csv
python -m prud_ecom --sales private/demo-sales.csv --ads private/demo-ads.csv --group period --output private/demo-report.csv
```

Все данные примера вымышленные: 4 чистых заказа, 4000 ₽ сумма заказов за вычетом отмен, 400 ₽ расход, 100 ₽ СПО, 10% ДРР. Маппинг переименовывает колонки уже агрегированной и проверенной таблицы. Он не заменяет разработку нативных парсеров.

Следующие этапы: проверка на разрешённых тестовых кабинетах, автоматическое преобразование нативных отчётов, загрузка готового архива Маркета, проверка полноты периодов, привязка кампаний к SKU и только после этого — автопилот.
